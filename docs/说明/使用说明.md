# 试炼使用说明

正式程序为`build/trial-spawner.exe`；`run.bat`读取`finder.properties`，命令行参数可覆盖配置。运行不需要Java或Minecraft。

## 参数

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--seed` | `0` | 有符号 64 位整数或文本种子；文本按 Java UTF-16 字符串哈希 |
| `--version` / `--generation` | 代际 `2` | `1.21`、`1.21.1` → 1；`1.21.2`–`1.21.11`、`26.1`、`26.1.1`、`26.1.2`、`26.2` → 2；`26.3` → 3 |
| `--radius`、`--center-x`、`--center-z` | `100000`、`0`、`0` | 搜索半径和中心，单位方块 |
| `--shape` | `circle` | 外层搜索 `circle` / `square`；方形半径为半边长 |
| `--cluster-radius`、`--cluster-shape` | `128`、`circle` | 每个结果的统计范围，独立于外层搜索形状 |
| `--min-structures`、`--min-spawners` | `2`、`20` | 最低实际密室数、窗口内最低**等效**笼数（`fast + slow*ratio`，与排名键一致；不是快慢总数） |
| `--conversion-ratio` | `1.0` | 慢速笼折算比例（0–1）；`fast + slow*ratio` 为排名键，`1.0` 等于旧的总笼数排名 |
| `--strict-mode`、`--strict-margin` | 关闭、`0` | 严格模式：只有起点离统计窗口边界 ≥边距的密室参与该组（结构数和笼数都只算它们）；笼数仍按完整窗口裁剪。窗口长/短边须 >2×边距（圆半径 >边距） |
| `--threads` | `8` | 1–32；线程越多内存越高 |
| `--limit` | `0` | 最终返回条数；每种密室数量的组容量为 `max(100, limit)`，`0` 表示不额外截断但仍按每种数量 100 条保留 |
| `--output` | `results` | CSV、TXT、JSON 输出目录；三份文件由同一份最终结果生成 |
| `--full-world` | 关闭 | 按世界边界裁剪的全图搜索；耗时随范围增长 |
| `--checkpoint-dir` | 输出目录下 `checkpoints` | 自动恢复相同参数的已完成分片；`--no-checkpoint` 关闭 |

## 严格模式

严格模式把“结构起点”的可行范围收紧到统计窗口四边各缩进 `--strict-margin` 格（默认 0，可在 `finder.properties` 用 `trial-strict-margin` 改）的内窗口，统计范围不缩小：

- 只有起点落在内窗口里的密室才参与这一组：它们计入结构数、满足最低密室数，并贡献笼子数。贴边的密室整间剔除——不会被算进结构数，也不贡献笼子；但不会因为一间贴边就丢掉整组，剩下的密室照常成组、照常排名。
- 笼子数量和快慢笼判定仍按**完整**窗口裁剪：内窗口成员的房间即使有一部分越过内边界（最多到完整窗口边界），也仍然计入。
- 只有起点落在内窗口里的密室才会被模拟；其他密室即使房间伸进完整窗口，也不参与这一组、不计笼子。
- 因此结果里的密室一定都是起点离窗口边界 ≥边距的完整密室，笼数也只来自这些密室；比普通模式更保守，但不会因为一间贴边密室而丢掉整组。
- 统计窗口半宽必须大于边距（矩形长/短边 >2×边距，圆半径 >边距），否则没有可用内窗口；CLI 会报参数错误。
- CLI 用 `--strict-mode` / `--strict-margin`；`finder.properties` 用 `trial-strict-mode` / `trial-strict-margin`；JSON `params` 输出 `strictMode`，开启时附 `strictMargin`。断点指纹在开启时额外加盐，普通模式的断点文件名不变。

## 单密室与搜索边界

`--chunk-x/--chunk-z`接收已知密室起点区块，返回`spawners`的XYZ；不检查它是否恰是种子放置起点。搜索统计在水平圆/方范围上求整数X/Z最佳中心，没有做三维球形激活优化，展示Y=-30不代表最优高度。

版本按生成代际：1.21–1.21.1为1，1.21.2–1.21.11及26.1/26.1.1/26.1.2/26.2为2，26.3为3。26.3独立计算float气候，派生几何与26.2相同；旧补丁没有逐版独立原版验证。

## 排名、导出和断点

折算笼数（`fast + slow*--conversion-ratio`）降序 → 距任务实际中心距离平方升序 → X、Z升序，在Top K截断前统一计算；`--conversion-ratio 1.0` 时等于总笼数排序，保持旧榜单。密室数只展示。每种密室数档位保留`max(100, limit)`，CLI的limit=0不是保留无限候选。

现在 `--min-spawners` 与排名键统一为等效笼数（`fast + slow*ratio`），不再是快慢总数；`--conversion-ratio 1.0` 时两者相同。注意：按旧的“快慢总数”口径保存的断点不会被自动作废，续跑前建议删掉旧断点目录。

默认断点在输出目录下的checkpoints，相同参数重跑自动恢复；线程数改变会影响分片，因此另用断点。成功导出后删除对应断点，取消和中途退出保留已保存分片。

CLI生成同一榜单的CSV/TXT/JSON；桌面`--jsonl`接受协议v3，默认延迟导出，由壳在用户保存时落盘。种子在JSON中保持字符串，计时包含恢复历史并扣除本次暂停。

引擎3.0.1起，JSON每条试炼结果新增`fastSpawnerCount`（快速笼数）、`slowSpawnerCount`（慢速笼数），
两者相加等于`score`。按最终中心的水平圆/方统计范围裁剪并按XYZ去重，不是成员密室全部笼子的累计。
`candidates.batch`、`done.result.candidates`及JSON导出使用同一份统计；总笼数排名、CSV/TXT列保持原样。
断点格式更新为`native-v5`，不读取缺少快慢统计的旧`native-v4`断点；旧断点文件保留。

引擎3.0.1起，JSON每条试炼结果新增`fastSpawnerCount`（快速笼数）、`slowSpawnerCount`（慢速笼数），
两者相加等于`score`。按最终中心的水平圆/方统计范围裁剪并按XYZ去重，不是成员密室全部笼子的累计。
3.0.2 起新增`convertedSpawnerCount`/`conversionRatio`，正式排名改为按折算笼数降序；
`--conversion-ratio 1.0` 保持旧的总笼数榜单。`candidates.batch`、`done.result.candidates`及JSON导出使用同一份统计。
断点格式为`native-v5`，不读取缺少快慢统计的旧`native-v4`断点；旧断点文件保留。

## 开发维护

普通构建用`build.ps1`；只有保留完整本地`tests/`、`tools/`及Python时才使用`build.ps1 -Test`。生成常量已包含在`data/`，数据生成工具不随仓库提交；修改数据后应自行验证。Cubiomes负责旧气候路径，布局与RNG由本仓库实现；来源见[许可](../../THIRD_PARTY.md)。

冻结参照与回归脚本位于不提交的`tests/`；不要把优化前C++对照样本数量当作同数量的原版验证。
